- **★ 识别 varargs 的可靠方法（2026-09-14 血泪总结）**：**cimgui 对 varargs 函数另有一个 `V` 后缀导出**——`igTextV`/`igLabelTextV`/`igSetTooltipV`/`igTextColoredV`/`igBulletTextV`/`igLogTextV` 等。
  **判断法：某导出若无同名 `V` 版本 → 非 varargs（可挂）；若有 → 是 varargs（禁止挂）。** 已用此法全量审计 21 个钩子，确认均非 varargs。
- **⚠ 事故复盘（2026-09-14）**：`igSetTooltip` 是 varargs（有 `igSetTooltipV`），我却用 `V1(nint)` 单参委托挂了它——**违反了本文件已记录的教训**。后果：`SetTooltip` 调用极频繁（鼠标悬停任意控件都触发）→ 持续栈腐蚀 → **游戏内 Ctrl+V 要按多次才粘贴成功**（输入事件被破坏，但界面显示正常，故极难定位）。**教训：加钩子前必须先用「V 后缀法」核对，不能凭"参数看着简单"就挂。**
- **✅ 已修：Ctrl+V 要按好几次才粘贴成功（2026-09-14 用户反馈）**：根因是**替换表重建卡顿**——`dalamud.log` 里有多条 `Long UiBuilder(翻译插件的插件) detected, 106~141ms > 100ms`。实测：合并表含 6.3 万条（wiki 6.2 万 + 安装器表 + 插件表），原 `RebuildMerged` 为**每条都预分配原生指针**（`StringToCoTaskMemUTF8`）→ `SetWikiTerms` 80ms、`Reload` 223ms。**ImGui 逐帧处理按键，卡 100ms+ 会丢输入事件**，故表现为「Ctrl+V 要按多次」。**修法**：①**惰性指针**——只给真正被渲染命中的条目建指针（`GetOrCreatePtr`）；②**增量更新**——单条增删改只动该条（`ApplyOneWindowEntry`/`RemoveOneWindowEntry`），不再全量重建。**效果：Reload 223→63ms、SetWikiTerms 80→55ms**（实测）。

### 本机 Dalamud 环境实测事实（2026-09-14，Dalamud 15.0.3.4，ApiLevel 15）
- **cimgui 导出全是极小的转发桩**（决定性证据：igBegin 与 igEnd 相邻仅 16 字节；ImGui::Begin 函数体几千字节）。**本机桩有两种形态**：igBegin 桩 = `E9 rel32`（跳模块内，正常转发）；ImDrawList_AddText_FontPtr 桩 = `FF 24 25 abs32`（jmp [绝对槽 0x3FF01A98]，槽里指向**别的模块** 0x7ff8cc8f19c0——挂上去永远拦不到，2026-09-14 日志实锤，这就是「只采到 Browsingway 标题、正文全漏」的根因）。**规则：解析出的目标在 cimgui 模块外一律判失败走 igTextUnformatted 兜底**（日志会记目标所属模块名）。兜底模式：igTextUnformatted 桩（托管 Text 类调用必经）+ Begin 标题采集，标题类文案两条路都通
  **教训链条**：①直接挂桩只能拦到「直接 P/Invoke 该导出」的调用——igBegin/igEnd 桩有效（插件 Begin 都走 P/Invoke），但 AddText 桩永远拦不到内部 C++ 渲染（RenderText 直调函数体），曾因此采到 0 条；②只认 E9 也不行（本机桩是 FF 24 25，解析失败又退回挂桩，第二次采到 0 条）；③模块外的目标不可信（挂了假地址，正文全漏只剩标题）；④**ImGui 控件函数全部返回 bool（是否被激活/展开），桩委托必须用 byte 接并原样返回——声明成 void 会丢返回值，控件读到垃圾返回值全部失灵（折叠展不开/复选框乱跳），2026-09-14 踩过并已修**；⑤**转发参数只能多不能少**（少一个，后面的参数全错位——igCollapsingHeader_BoolPtr 实为 3 参含 flags，少转发导致折叠头读到垃圾 flags，已修）；⑥**⚠ 控件桩钩子会崩游戏，默认关闭**：崩溃堆栈实锤（安装器 IconButton → P/Invoke igButton(IntPtr,ImVec2) → ReversePInvoke → Button+0x16 AV 0xC0000005，游戏退出），修完 bool/参数个数后仍崩，疑似打包桩（packed stub）的 ReversePInvoke/重定位问题——**文本桩钩子（igTextUnformatted 2 参 void / igBegin byte 返回 / igEnd void）连跑数小时稳定**。控件标签采集能力暂停，文案需求由静态扫描顶；恢复此能力前需先解决桩钩子崩溃机理（可试 MinHook 后端、或只挂纯转发桩）。⑦**Hook 实例必须 ref/holder 传回调用方**：InstallWindowHook 曾按值收 Hook 参数，赋值留在副本上→调用方变量恒 null→detour 一触发抛 NRE→后端吞异常但原函数不执行→凡路过该桩的 UI 绘制整段静默失效（标题栏 ≡ 附加选项菜单打不开、▼ 折叠行为错乱，2026-09-14 踩过已修）；detour 内必须 try/catch。⑧detour 委托避免按值结构体参数（ImVec2 反向封送疑似不可靠=igButton 崩溃疑似机理）。⑩**⚠⚠ 统一根因：按值结构体（含 float）参数的函数绝不能用 .NET 委托挂**（2026-09-14 最终定论）：`ImVec2` 是「两个 float 的结构体」，Windows x64 约定它走 **XMM 寄存器**传参，而 .NET 封送器对「只含 float 的 ≤8 字节结构体」可能按**通用寄存器**传（已知 interop 陷阱）→ 每次调用参数错位 → 写坏调用方栈/ImGui 内部状态。**一个根因解释全部症状**：igButton（含 ImVec2）崩游戏；ImDrawList_AddText_FontPtr（含 ImVec2）把 ImGui 状态弄坏 → 标题栏 ≡ 菜单/▼ 折叠静默失灵（与 varargs 栈腐蚀叠加）；igBegin（无 ImVec2，byte 返回）、igTextUnformatted（纯指针）长期稳定。**故 AddText 路线彻底删除**——即使解析出真实函数体也不能挂。**关键运维事实：插件重载不会重置 ImGui 上下文**，被坏钩子写坏的状态只有**重启游戏进程**才清得掉（曾出现「已改好但重载无效」的假象，用户误以为修复失败）。要恢复全文字覆盖（含按钮标签）的唯一正路：**原生跳板（C++ detour）或换钩子后端**，不用托管委托挂这类函数。**最终钩子白名单 = igTextUnformatted（2 指针 void）+ igTextEx（2 指针 + int，ImGui 文字族总入口）+ 20 个安全控件标签桩**（2026-09-14 最终版）：

  - 路径是 `ImGui.SliderFloat(...)`（托管）→ `ImGui::SliderScalar<float>`（托管泛型）→ `ImGuiNative::SliderScalar`（生成的 native 包装）→ `HexaGen.Runtime.FunctionTable[185]` → cimgui 导出 **`igSliderScalar`**。

  - **结论：想要拦 SliderFloat/SliderInt/DragFloat/DragInt 这类"模板化标量"控件，必须挂 `igSliderScalar`/`igSliderScalarN`/`igDragScalar`/`igDragScalarN`，而不是 `igSliderFloat`/`igDragFloat`**（后两者在托管 API 路径上根本不触发——这就是"钩子明明挂上了、调用计数却是 0"的根因）。已补挂这 4 个标量导出。

  - **同法核出的其它真实落点**：组合框标签是 **`igCombo_Str`**（不是 `igBeginCombo`——后者管的是"展开时的下拉定义"）；大取色器是 **`igColorPicker3/4`**（与"小色块" `igColorEdit3/4` 是两个控件）；另有 `igTableHeader`（表头文字）、`igSliderAngle`。这些标签都是**画出来的文字**且签名安全，已一并补挂。
  - **同一坑的通用教训**：判断"某托管 API 落到哪个导出"不能靠名字猜，要顺着 `ImGui.X → ImGui::Y<T> → ImGuiNative::Z → FunctionTable[i] → 导出名` 这条链查 IL；`#US` 堆里的导出名是 UTF-16LE。
