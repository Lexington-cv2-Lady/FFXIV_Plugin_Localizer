## 二、`.Tests.csproj` 模板

### 2.1 项目一 `FFXIV_MOD选项汉化工具_卫月插件版`

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <IsPackable>false</IsPackable>
    <LangVersion>latest</LangVersion>
    <!-- 主工程有 unsafe（ReplacementService 等），引用它时测试工程也要开 -->
    <AllowUnsafeBlocks>true</AllowUnsafeBlocks>
    <!-- 与主工程一致，避免平台不匹配 -->
    <Platforms>x64</Platforms>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="Microsoft.NET.Test.Sdk" Version="17.11.1" />
    <PackageReference Include="xunit" Version="2.9.2" />
    <PackageReference Include="xunit.runner.visualstudio" Version="2.8.2" />
  </ItemGroup>

  <ItemGroup>
    <!-- 方式一（先试这个）：直接引用主工程 -->
    <ProjectReference Include="..\FFXIV_Penumbra_Mod_Chinese_Localization_Plugin\FFXIV_Penumbra_Mod_Chinese_Localization_Plugin.csproj" />
  </ItemGroup>

</Project>
```

> **⚠ 坑 1**：项目一 `JsonFile` 是 **`internal static class`**。若走「方式一」引用工程，测试要访问它须在主工程加
> `<ItemGroup><InternalsVisibleTo Include="FFXIV_Penumbra_Mod_Chinese_Localization_Plugin.Tests" /></ItemGroup>`
> （.NET SDK 支持该项，自动生成 `InternalsVisibleTo` 特性）。
> **⚠ 坑 2**：主工程有 `DeployToDev` Target（`AfterTargets="Build"`）会往 devPlugins 复制——**CI 上该目录不存在会报错**。两个办法：①CI 里加 `/p:DevPluginDir=$(Agent.TempDirectory)\devPlugins`；②或用「方式二」只链接纯逻辑源文件（见下），不触达打包链。

### 2.2 项目二 `FFXIV_汉化插件的插件`

同 §2.1，只改两处：

```xml
    <ProjectReference Include="..\FFXIV_Plugin_Localizer\FFXIV_Plugin_Localizer.csproj" />
```

> `ReplacementService` 为 `public sealed unsafe class` → 同样需要 `<AllowUnsafeBlocks>true</AllowUnsafeBlocks>`（已在模板里）。

### 2.3 备选「方式二」：只链接纯逻辑源文件（不拉 Dalamud 依赖）

若「方式一」因 Dalamud 程序集拉不动（CI 未装 Dalamud / 版本不合），可只把**纯逻辑**文件链进测试工程：

```xml
  <ItemGroup>
    <Compile Include="..\FFXIV_Plugin_Localizer\Services\TextHeuristics.cs" Link="src\TextHeuristics.cs" />
    <Compile Include="..\FFXIV_Plugin_Localizer\Services\JsonFile.cs"        Link="src\JsonFile.cs" />
  </ItemGroup>
```

> 代价：这些文件里若引用了 Dalamud 类型，仍会编不过——只适用于**完全无 Dalamud 依赖**的纯逻辑文件（`TextHeuristics`、`JsonFile` 属此类）。

### 3.1 项目二：`TextHeuristics` 判据（最易回归，优先覆盖）

```csharp
using Xunit;

public class TextHeuristicsTests
{
    // 「译文 == 原文」必须判为有效（FFXIV 母本 B.5：URL/DPS/HP 原样返回是正确答案）
    [Theory]
    [InlineData("URL", "URL")]
    [InlineData("DPS", "DPS")]
    public void IsValidMachineTranslation_SameAsSource_IsValid(string en, string zh)
        => Assert.True(TextHeuristics.IsValidMachineTranslation(en, zh));

    // 空译文必须判为无效（要留着重试；曾把空值当成功导致进度卡 n-1/n）
    [Fact]
    public void IsValidMachineTranslation_Empty_IsInvalid()
        => Assert.False(TextHeuristics.IsValidMachineTranslation("Attack", ""));

    // CJK 判定：中文有、英文无
    [Fact]
    public void HasCjk_ChineseTrue_EnglishFalse()
    {
        Assert.True(TextHeuristics.HasCjk("攻击"));
        Assert.False(TextHeuristics.HasCjk("Attack"));
    }

    // 去 ImGui 内部 ID 后缀
    [Theory]
    [InlineData("显示文字##internal_id", "显示文字")]
    [InlineData("Normal", "Normal")]
    public void StripIdSuffix_RemovesInternalId(string input, string expected)
        => Assert.Equal(expected, TextHeuristics.StripIdSuffix(input));
}
```

### 3.2 项目一：`JsonFile.WriteAtomic` 原子写（通用母本 B.7 红线）

```csharp
using System;
using System.IO;
using Xunit;

public class JsonFileAtomicWriteTests
{
    [Fact]
    public void WriteAtomic_LeavesNoTempFile_AndContentIntact()
    {
        var dir  = Path.Combine(Path.GetTempPath(), "pmh_test_" + Guid.NewGuid().ToString("N"));
        Directory.CreateDirectory(dir);
        var path = Path.Combine(dir, "d.json");
        try
        {
            JsonFile.WriteAtomic(path, "{\"a\":1}");

            Assert.True(File.Exists(path));                 // 目标存在
            Assert.Equal("{\"a\":1}", File.ReadAllText(path)); // 内容完整
            Assert.False(File.Exists(path + ".tmp"));       // 无残留 .tmp（原子写标志）
        }
        finally { Directory.Delete(dir, true); }
    }
}
```

> ⚠ `.tmp` 后缀以**主工程实际实现**为准（通用 B.7 约定「先写 .tmp 再 `File.Move` 覆盖」，具体命名请对照 `JsonFile.WriteAtomic` 源码调整断言）。**照抄前先读一眼源码**。

## 四、CI 工作流模板

### 4.1 通用 `build-test.yml`（推荐新建，两项目通用）

```yaml
name: Build & Test

on:
  pull_request:
  push:
    branches: [ main ]        # 项目一默认分支是 master → 改成 master

jobs:
  build-test:
    runs-on: windows-2022
    steps:
    - name: Checkout
      uses: actions/checkout@v5

    - name: Install .NET
      uses: actions/setup-dotnet@v5
      with:
        dotnet-version: 10.0.x

    - name: Download Dalamud
      run: |
        Invoke-WebRequest -Uri https://goatcorp.github.io/dalamud-distrib/latest.zip -OutFile latest.zip
        Expand-Archive -Force latest.zip "$env:AppData\XIVLauncher\addon\Hooks\dev"

    - name: Restore
      run: dotnet restore

    - name: Build
      run: dotnet build --configuration Release --no-restore /p:DevPluginDir="${{ runner.temp }}\devPlugins"

    - name: Test
      run: dotnet test --configuration Release --no-build --verbosity normal
```

> `/p:DevPluginDir=` 用来把 `DeployToDev` 的复制目标改到临时目录，**避免 CI 上 devPlugins 不存在而报错**。

### 4.2 项目一 `pr-build.yml` 修正对照

现有文件的问题（实测）：

| 位置 | 现值（模板残留） | 应改为 |
|---|---|---|
| `name` | `Sample PR Builder for SamplePlugin` | `Build & Test`（或自定） |
| `env.Solution_Name` | `SamplePlugin` | `FFXIV_Penumbra_Mod_Chinese_Localization_Plugin`（或整项删除） |
| artifact `name` | `SamplePlugin` | 同上真实名 |
| artifact `path` | `.\SamplePlugin\bin\x64\Release\SamplePlugin\*` | `.\FFXIV_Penumbra_Mod_Chinese_Localization_Plugin\bin\Release\*` |

> `bin\Release\` **没有** `x64` 与 TFM 子目录（Dalamud.NET.Sdk 压平了输出路径），故原路径既错在目录名、也错在多写的 `x64\`。
> `SamplePlugin.slnx` 文件名为模板残留（内容正确），可按需改名。

## 六、注意事项速查

| 事项 | 要点 |
|---|---|
| 目标框架 | 两项目 **`net10.0`**；测试工程须一致 |
| 输出目录 | `bin\<Configuration>\`，**无 TFM / 无 x64 子目录** |
| `internal` 类型 | 项目一 `JsonFile` 是 internal → 需 `InternalsVisibleTo` 或走「方式二」链源文件 |
| `unsafe` | 项目二 `ReplacementService` 是 unsafe → 测试工程 `<AllowUnsafeBlocks>true</AllowUnsafeBlocks>` |
| Dalamud 依赖 | CI 必须先 `Download Dalamud`；否则引用主工程会还原失败 |
| `DeployToDev` | `AfterTargets="Build"`，CI 上须 `/p:DevPluginDir=` 改道 |
| 覆盖优先级 | **高危逻辑 > 覆盖率数字**（母本 B.26）：原子写、缓存失效、判据、闭环、并发 |
